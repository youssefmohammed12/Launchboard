## 1. Product direction

Launchboard remains a personal opportunity-management and career-tracking workspace. People discover opportunities on external platforms; Launchboard helps them organize those opportunities, decide what to do next, follow up, and learn from their activity. It must not become a job marketplace or an automatic application service.

The v1.2 goal is to make Launchboard more action-oriented without making it feel like a separate general-purpose project-management product.

## 2. Release scope — balanced

### 2.1 Task management

Introduce a unified task concept that supports multiple actions for one opportunity. The intended user capabilities are:

- Create, edit and delete tasks associated with an opportunity.
- Give each task a clear title and optional details.
- Set a priority and an optional due date.
- Mark a task complete and reopen it when necessary.
- See the opportunity associated with each task and navigate back to it.
- Keep task completion separate from changing the opportunity's application status.

The task shape and rules are resolved in `docs/v1.2-action-center-design.md`: opportunity-owned task records with title, notes, reused priority, optional date-only due date, completion flag and completion date. Stage 2 integrates the collection into localStorage normalization/recovery, v2 JSON backups and the authenticated API aggregate. Stage 3 implements the task lifecycle operations in domain/local/API layers; user-facing CRUD controls remain in Stage 4.

### 2.2 Action Center

Add a dedicated place to answer “What should I do next?” It should make these groups easy to scan:

- **Overdue** — incomplete tasks whose due date has passed.
- **Today** — incomplete tasks due on the current local calendar date.
- **Upcoming** — incomplete tasks with a future due date.
- **Unscheduled** — incomplete tasks without a due date.

Task groups use the shared deterministic ordering rules. Provide a priority selector and a completion-state toggle (completed tasks are shown separately by default). Completing a task should update the relevant views immediately and remain persistent after reload.

### 2.3 Dashboard integration

Add a compact **Today** area to the Dashboard showing the most relevant due-today and overdue work, with a direct path to the full Action Center. Keep the Dashboard a summary, not a second task-management screen.

### 2.4 Calendar integration

Show dated tasks in the existing Calendar alongside existing opportunity-related dates. Make task entries visually and semantically distinguishable from deadlines, interviews and follow-up dates. Selecting a task should open its task/opportunity context and must not accidentally change an existing opportunity date.

### 2.5 Reminder behavior for v1.2

The first release should provide reliable in-app visibility through the Action Center, Dashboard and Calendar. Browser push notifications, email reminders, background scheduling and mandatory third-party services are out of scope for v1.2.

## 3. Data and compatibility principles

The Action Center must respect the existing architecture:

- Browser localStorage remains the default mode. Authenticated API mode remains opt-in.
- Shared task contracts, controlled values and pure validation/date rules belong in `@launchboard/domain`; browser recovery policy remains in the frontend.
- Local persistence and the API must implement the same user-visible task behavior without collapsing their intentionally different write contracts.
- API writes must retain strict validation, account ownership, optimistic version checks and transactional aggregate updates.
- Date-only values must follow the existing local-calendar `YYYY-MM-DD` rules. Do not introduce UTC date shifts.
- Existing opportunity records, local recovery data, saved views, backups and user-created content must remain compatible.
- Any persisted-shape change requires an explicit backward-compatible local-data/backup strategy and, if needed, a new additive database migration. Never edit an already-applied migration.
- Backup export/import, restore behavior and migration tests must be considered before the feature is called complete.

### Existing dates must not be duplicated

Opportunities already have deadline, follow-up and interview-related dates. Stage 0 traced their current sources and Calendar behavior. They remain distinct records and events; no automatic task conversion or second editable representation will be introduced. See `docs/v1.2-action-center-design.md` for the decision record.

## 5. Acceptance criteria

v1.2 is ready for release only when:

1. A user can create and manage multiple tasks for an opportunity without changing that opportunity's application status.
2. Task priority, optional due date and completion state persist correctly in both local and API modes.
3. Overdue, Today, Upcoming and Unscheduled groups classify incomplete tasks consistently using local calendar dates.
4. The Dashboard Today summary agrees with the Action Center.
5. Dated tasks appear in Calendar and remain distinguishable from existing deadlines, interviews and follow-up dates.
6. Existing opportunity dates are not duplicated or silently converted into tasks.
7. Existing local data, backups, restore flows and API-mode data remain safe and compatible.
8. API ownership, validation, optimistic concurrency and transaction guarantees remain intact.
9. The feature is usable with keyboard and touch input at phone, tablet and desktop sizes.
10. The full release verification is recorded in the project documents.

## 6. Explicit non-goals

- Job/opportunity marketplace, job scraping or automatic applications.
- Browser extension and external-platform integrations (candidate for v1.3).
- Email or push notifications, mandatory calendar connection or paid third-party services.
- AI opportunity analysis or chatbot.
- Weekly goals/review, advanced analytics or reusable document library (later roadmap items).
- Recurring tasks, complex dependencies, subtasks, team collaboration or a generic project-management system unless discovery establishes a compelling need.

## 7. Resolved Stage 0 decisions

- Every task belongs to exactly one opportunity and is stored as an opportunity child.
- Task priority reuses Low, Medium and High. The initial task limit is 100 per opportunity; title and notes limits are 160 and 1,000 characters.
- The task lifecycle is open/completed. Completion records a local date; reopening clears it.
- Existing deadline, follow-up, interview and activity records remain distinct and are never automatically converted into tasks.
- The Action Center is derived from tasks on active opportunities; archived opportunities and their tasks are excluded until restored.
- Local mode keeps the existing collection key and recovery policy. API mode extends the existing versioned opportunity aggregate and transaction.
- JSON exports move to schema v2 with v1 import compatibility. CSV remains a tabular summary.
- v1.2 reminders are in-app only; no email, push or paid integrations are required.

The complete findings, proposed schema and implementation boundaries are in `docs/v1.2-action-center-design.md`.

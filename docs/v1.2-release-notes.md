# Launchboard v1.2.0 — Action Center

**Release status:** v1.2.0 released to production and versioned in Git as `ui-v1.2.0`
**Verification date:** 2026-11-07
**Working branch:** `feature/action-center-v1.2`
**Release baseline:** `ui-v1.1.0` / `38cadda`

## What's included

- **Opportunity-linked tasks:** create, edit, complete, reopen and delete multiple tasks attached to an opportunity. Tasks support a title, optional notes, Low/Medium/High priority and an optional date-only due date.
- **Action Center:** organize active-opportunity tasks into Overdue, Due today, Upcoming, No due date and Completed groups. Filter by priority, show/hide completed work and navigate back to the owning opportunity.
- **Dashboard Today's Focus:** surface overdue and due-today open tasks, with direct navigation to the relevant Action Center task. The existing Next 7 Days summary remains dedicated to deadlines, follow-ups and scheduled interviews.
- **Calendar task events:** view dated open tasks through a distinct Tasks filter. Selecting a task opens its matching Action Center task. Existing deadline, follow-up and interview records remain separate and are not converted into tasks.
- **Local and API modes:** both modes share the task behavior. Local writes use the existing recovery-aware collection storage; authenticated API writes reuse the versioned opportunity aggregate, ownership checks and transaction boundary.

## Data and backup compatibility

- The existing localStorage key is retained. Older opportunity records without a `tasks` collection normalize to an empty collection.
- JSON backup export uses schema v2. Schema v1 imports remain supported and normalize to empty task collections; v2 imports preserve task data, including completed and unscheduled tasks.
- CSV remains a tabular summary, not a full-fidelity backup. JSON is the full backup format.
- Additive migration `004_opportunity_tasks.sql` creates the API-side task storage. It was applied to the dedicated production `launchboard` TiDB database after a verified logical backup, using the separate migration account. The migration history contains migrations 001–004 with repository-matching checksums; the live verifier confirms the `tasks` table, columns, indexes and foreign key. Existing task data started empty, as expected for this additive release.

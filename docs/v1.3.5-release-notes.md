# Launchboard v1.3.5 — Account & Opportunity Workflow Polish

**Version:** v1.3.5
**Update date:** 10 November 2026
**Release status at final review:** Application candidate and API-mode deployment package prepared locally; hosted migrations 006 and 007 applied and verified. The application source is awaiting its reviewed release commit, Preview validation and Production deployment.
**Release branch:** `feature/quick-capture-v1.3`
**Production application:** The deployed application remains v1.3.0 until a separately approved release.

## Summary

v1.3.5 brings account self-service, more reliable opportunity details, and clearer account emails. It also improves Quick Capture's handling of generic pages, makes calendar/dashboard date summaries more accurate, adds Contract as an opportunity type, and includes the verified additive database changes.

## What changed

### Account Settings

- Added a dedicated **Settings** page for signed-in users, reachable from the account navigation.
- Added an optional profile display name. Users can set or update up to 80 characters; the name is reflected in the signed-in header and mobile account menu.
- The sign-in email and verification state are visible but read-only. Email-address changes are intentionally not included because they require a separate verify-new-address workflow.
- Added a password-change flow that requires the current password and enforces the existing 15-character minimum password policy.
- Password changes are conditional and transactional. The current session is rechecked, other active sessions are revoked, and the current browser session remains signed in.
- Added account deletion with current-password verification and an exact `DELETE` confirmation. The UI warns users to export a JSON backup first. The server removes interview rows first to respect the existing interview-to-contact RESTRICT relationship, then deletes the user in a transaction so the user-owned records and sessions are removed through the existing foreign-key cascades.
- Account mutations require the authenticated session, exact trusted Origin, JSON content type, authenticated CSRF token, strict request schemas and separate IP rate limits. Account responses use no-store caching.

### Opportunity data and capture improvements

- Added **Contract** as an Opportunity tracking type and removed the implicit Internship default. New opportunities require the user to choose a type explicitly; existing records keep their stored type.
- Migration 007 extends the database type constraint with Contract without rewriting any existing opportunity rows. TiDB requires the old CHECK constraint to be dropped and the new one added as two ordered ALTER statements; the combined form was rejected by TiDB 8.5.3. The split migration passed a temporary-table DDL probe before the repository migration runner applied it to Launchboard.
- Normalize employer workplace details on form load/save: workplace mode is kept separate from physical locations and employer employment type, duplicate/empty locations are removed, and explicit user choices take precedence over inferred mode.
- Strip UTM campaign parameters from opportunity URLs when saving while retaining meaningful query parameters and the original user input for malformed/non-HTTP URLs.
- Opportunity details now present employment type, work mode and locations separately, with clearer empty-activity guidance.
- Quick Capture no longer accepts generic marketing/careers-page metadata as a useful result unless job-specific evidence is present. Unsupported pages remain available for manual entry with the URL preserved, and the retry action reflects whether useful suggestions exist.
- Calendar month labels now include the related opportunity title, and the Dashboard's Next 7 Days range includes only the intended inclusive seven-day period.

### Branded account emails

A shared responsive Launchboard email design now provides matching HTML and plain-text versions for:

- New-account email verification.
- Resending an email-verification link.
- Password-reset requests.
- Password-change notification after a successful password reset.
- Password-change notification after a change made from Account Settings.

The templates use consistent Launchboard branding, accessible button/link fallbacks, clear account-action wording, security notices and the applicable token-expiry information. Existing fragment-based action URLs and one-time token behavior are preserved. Verification links remain valid for 24 hours and password-reset links for one hour.

The existing Gmail SMTP transport sends the plain-text part and optional HTML part together. No SMTP credentials or production email settings were changed. Automated tests cover template content, escaping, fallback links, expiry/security messaging and HTML transport. A live Gmail inbox rendering check was not completed, and no test email was sent during this release-preparation task.
